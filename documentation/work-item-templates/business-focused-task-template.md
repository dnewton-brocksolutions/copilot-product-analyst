## Usage Guidelines

### Focus On Business Value ✅

- **What** business problem this solves
- **What** users need to accomplish
- **What** data they need to see/input
- **What** the successful outcome looks like

### Avoid Technical Prescription ❌

- **How** to implement (frameworks, patterns, architecture)
- **Which** specific technologies to use
- **How** to structure code or databases
- **What** technical patterns to follow

### Technical Context Guidelines ✅

Provide just enough context to help developers know where to start:

- **Application** - Which app (OeeWeb, ProcessingMes, etc.)
- **Service** - Which backend service (if applicable)
- **Database Tables** - Key tables involved (if known)
- **Similar Features** - Existing features to reference
- **Dependencies** - Other tasks or services required

**Balance:** Give developers a starting point, but don't prescribe the implementation path.

**Remember:** Describe the destination AND the starting point, let developers choose the route!
